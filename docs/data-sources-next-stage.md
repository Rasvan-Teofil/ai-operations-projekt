# Next data version: publication-oriented, shared comparison

Source review: **6 November 2026**. Status: **proposal, no new training or test evaluation performed**. Existing v1/v2 and local-Qwen results remain historical. The local LLM currently used is **Qwen3-4B-Instruct-2507**, not Gemma. See the [shared licence inventory](../licenses/inventory.json), [notices](../licenses/README.md) and [website](http://127.0.0.1:8000/licenses).

The question remains useful to media monitoring and PR: does a German or English news item report a materially adverse outcome, no directional outcome, or a supported favourable outcome? Commercially reusable text and labels aligned with that decision are both necessary. An open annotation licence alone does not clear publisher text; a neutral journalistic style does not imply a neutral outcome.

Wikinews is an archive, not a continuing fresh-news source: the [Wikimedia board announcement](https://meta.wikimedia.org/wiki/Wikimedia_Foundation_Board_noticeboard/Archives/2026#Board_of_Trustees_Approves_Closure_of_Wikinews) specifies read-only mode from 4 May 2026. Its historical coverage and selection bias will need reporting. Public LLM pretraining overlap cannot be ruled out for any public archive.

**No ready-to-train bilingual, human-labelled, publisher-cleared general-news corpus has been established by this review.** The workable route is openly licensed native DE/EN text plus new human annotation. The two labelled candidates are not silently approved. This avoids claiming a licence problem solved merely by finding a permissive badge.

## Why the old sources do not become the new training pool

[Kenpache's pinned usage statement](https://huggingface.co/datasets/Kenpache/multilingual-financial-sentiment/blob/9d43950d151602f623f28bba62f30554b5d40dd2/README.md) restricts use to academic/non-commercial research and retains publisher rights, despite its Apache badge. [Financial PhraseBank](https://huggingface.co/datasets/takala/financial_phrasebank/blob/8d3fe0c36d5feec6b3cc5e455b0fcb4820fb9964/README.md) declares CC BY-NC-SA 3.0 and directs commercial users to its authors. Keep both out of the proposed publication-oriented pool absent separate permission. This does not prohibit reporting academic aggregate results.

[SEntFiN's MIT repository notice](https://github.com/pyRis/SEntFiN/blob/eba43610fe3cb57a3e5773cd6c037da1f8992ad5/LICENSE) does not establish original-publisher headline permissions in this review. Current results use it for evaluation; we publish metrics and split hashes, not headline text. Previously inspected tests also cannot become a fresh final test. OPUS-MT's permissive model licence does not change these source-text questions.

## Proposed protocol · `common-data-v3` · not frozen yet

1. **Rights and provenance first.** Select only original text with verified compatible terms. Store page/revision ID, canonical URL, language, publication date, author/history link, licence URL/version, retrieval date, text SHA-256 and changes per item. Exclude images, copied third-party passages, ambiguous licences and duplicates. Publish attribution with any eventual corpus release; do not relicense CC BY 2.5 text as our own CC BY 4.0 text. The licence for new project annotations still needs an explicit author decision.
2. **Label the actual decision.** Define the affected entity/audience before annotation. Negative = evidenced harm, loss, material risk or deterioration; positive = evidenced benefit, recovery or improvement; neutral = no supported directional outcome. Factual reporting can be negative. Mere positive wording is insufficient. Mixed outcomes and missing/unclear targets require adjudication or exclusion with recorded reason, not default neutral. Two fluent human annotators per language, blind to model predictions, independently label; adjudicate disagreements and report agreement and exclusions. LLM output is not gold. Article labels and sentence labels are separate tasks; the current highlight view is not gold span evidence.
3. **Freeze the data split.** Proposed seed `20261107`; 70/15/15 train/Val/test, stratified by language and label at group level as feasible. Keep full article, paraphrases, translations, duplicate snippets and same-event stories together. Group on article/event provenance before splitting; document residual overlap uncertainty. Keep earlier project tests and near-duplicates outside training and this fresh test. Corpus size and class balance must be frozen after collection/annotation, before experiments; no achieved size is claimed now.
4. **Rebuild comparable recipes.** Preserve historical artifacts. Refit the colleague-style LinearSVC recipe on the new Train; rebuild the frozen-encoder baseline and own MiniLM v2 recipe from the original permissively licensed base, using the same Train and preprocessing contract. Do not initialize from the Kenpache fine-tune. This measures the old recipes under the new data version without editing `main`. Name every run by recipe **and** data version. New data means new scores, not corrections to old scores.
5. **Local LLM condition.** Keep Qwen zero-shot as a separately identified condition on the exact same final texts. It uses no project training examples, so do not claim identical training histories. Freeze prompt, model revision, truncation and label-score method before test. If Gemma is later added, inspect its own terms and pre-register it as an additional model; do not rename the current Qwen run. No architecture-causality claim: base pretraining differs and public-text contamination is unknown.
6. **Training-only development.** Use grouped cross-validation inside Train for any permitted recipe/prompt changes; log separate ablations and one combined candidate. Val may only stop training under a predefined stopping rule, not choose the winner. Freeze candidates before the final test. Do not use the current SEntFiN test to tune this stage.
7. **One final evaluation.** Each frozen candidate predicts the same fresh native-English and native-German test once. Proposed primary selection score = arithmetic mean of EN macro-F1 and DE macro-F1, equal language weight; within absolute `0.005` of best choose lower warm batch-one latency, then total artifact size. Freeze this choice before seeing outcomes. Report pooled macro-F1, per-language/per-class F1, accuracy, confusion matrices, paired group-bootstrap intervals and the limits of a small test. Native DE replaces translation-only evidence; it does not make old tests numerically comparable.
8. **MLflow and deployment.** Keep experiment `article-sentiment-second-path`; new tags `phase=common-data-v3`, `recipe`, `data_version`, `comparable_group`, source/split hashes and Git commit. Every candidate run records parameters, accuracy, macro-F1, F1 per class, `inference_ms_per_text`, complete artifact size and confusion matrices, with per-language diagnostics. Measure on the same tower, batch 1, warm-up separate from test, CUDA synchronized, tokenization/transfers included; download/loading/URL fetch excluded. Record CPU threads, precision and device. Keep weights in ignored `models/` and data outside Git. Preserve old MLflow runs. Update serving selection, comparison bars, website licence inventory and README together only after completion and rights review; a faster, smaller classifier may win under the declared close margin.

Before this protocol can be frozen: obtain human labels, inspect selected page revisions, choose the annotation licence with its authors, and resolve any optional source permissions. Those are real prerequisites, not results already obtained. No new MLflow training run is created for a documentation-only source review.
